EXPRESSIONS §3.10

match and patterns

A match expression produces a value. Here are the matching order, exhaustiveness rules and guard semantics.

SyntaxExhaustivenessPatternsSource

Arms are checked in order

Arms are tested top to bottom. The expression from the first matching pattern and guard is evaluated. Every arm must have the same result type.

match expression { pattern -> result }The selected arm produces the match value
Failed error when retryable error -> "retry"A Bool guard is checked after the pattern

Exhaustiveness and unreachable arms

All cases must be covered. Missing cases and unreachable arms are compile errors. Guarded arms do not count towards exhaustiveness because their Bool condition may be false.

Pattern forms

Patterns may nest literals, bindings, _, constructors, tuples, records, structs, arrays and lists. A name cannot be bound twice within the same pattern.

This complete example matches a tuple of remainders from division by 3 and 5; all arms return a String.

Try in Playground ↗
fn fizzBuzz number: Int -> String =
  // A tuple lets one match classify both divisibility rules.
  match (number % 3, number % 5) {
    (0, 0) -> "FizzBuzz"
    (0, _) -> "Fizz"
    (_, 0) -> "Buzz"
    _ -> `${number}`
  }

pub effect fn main = for number <- 1 ..= 30 {
  println $ fizzBuzz number
}
Output (first five lines)1 2 Fizz 4 Buzz …
