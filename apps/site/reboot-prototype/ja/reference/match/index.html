EXPRESSIONS §3.10

match とパターン

match は値を分岐する式。どのパターンに一致したかによって、式全体の値が決まる。ここでは評価の順序、網羅性、guardのルールまで確認する。

構文と評価網羅性パターン仕様出典

パターンを上から照合する

最初にpatternとguardが一致した枝を選んで、その右側の式を評価する。すべての枝の結果型は一致しなければならない。

match expression { pattern -> result }一致した枝の結果がmatch全体の値になる
Failed error when retryable error -> "retry"patternが一致してからBoolのguardを評価

網羅性と到達不能な枝

すべての場合を覆う必要がある。 足りないケースがあればコンパイルエラー。すでに必ず一致する枝の後にある到達不能な枝もエラー。guard付きの枝は、条件がFalseになる可能性があるため網羅性には数えない。

組み合わせられるパターン

リテラル、変数束縛、_、constructor、tuple、record、struct、Array、Listのパターンを入れ子にできる。同じpattern内では同じ名前を二度束縛できない。

3と5で割った余りをタプルとして照合する完全な例はこちら。各枝は文字列を返す。

fn fizzBuzz number: Int -> String =
  // A tuple lets one match classify both divisibility rules.
  match (number % 3, number % 5) {
    (0, 0) -> "FizzBuzz"
    (0, _) -> "Fizz"
    (_, 0) -> "Buzz"
    _ -> `${number}`
  }

pub effect fn main = for number <- 1 ..= 30 {
  println $ fizzBuzz number
}
出力（先頭5行）1 2 Fizz 4 Buzz …
