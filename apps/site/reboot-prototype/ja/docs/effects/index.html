Guide / Effectとdo
04 / VALUES, EFFECTS, EXECUTION

計算を作ることと、動かすこと。

関数から値を作ることと、ファイルを読む・表示する・通信することは同じではない。Seseragiでは、外の世界に触れる計算を Effect という値で表す。「実行する処理」を、まず「組み立てられるもの」にするんだ。

純粋な計算には、外の世界が要らない。

例えば、ラベルの両端の空白を取り除いて、文字数を合計したい。文字列と配列だけで決まるなら、これは普通の値の計算。

01 / 抜粋：値を計算する
let labels = [" Build ", "bundle", "CHECK", "run"]
let lengths = map (\label -> text.lengthScalars (text.trim label)) labels
let total = reduce 0 (+) lengths

map で各ラベルの長さを求め、reduce で足している。得られる長さは [5, 6, 5, 3]、合計は 19。この計算そのものはconsoleも、ファイルも必要としない。

出力したいとき、何が変わる？

数を計算することと、その数をconsoleへ書くことには違いがある。println は単なる Unit を返す普通の純粋な関数ではなく、consoleという外部の環境を必要とするEffectを作る。

Effect<R,E,A> の3つの型引数は、順番に必要な環境 R、回復可能な失敗 E、成功値 A。コンパイラは、それぞれの計算が何を必要とし、どう失敗し得るかを型から追える。

例えば pub effect fn main は、実行境界となるEffectを返すエントリーポイント。effect fn を宣言しただけで副作用が勝手に起きるわけじゃない。

do は、Effectだけの特別扱いではない。

ここは誤解しやすいところ。do は Monadに対するbindの列を読みやすく書く構文で、EffectやTask専用じゃない。Maybe や他のMonadでも、同じ構造の合成を表せる。

THE MEANING OF DO
読みやすいdoの形
do {
  x <- mx
  next x
}
≡
bindで表すと
mx >>= (\x -> next x)

mx は M<A>、next は前の値から次の M<B> を作る関数だと考えてほしい。上の式は展開の意味を表す模式図で、独立して実行するプログラムではない。

do の途中では x <- mx で値を取り出して次へ渡せるし、let x = ... で純粋な名前も導入できる。最後には同じMonadの式が必要で、違うMonadを暗黙に混ぜることはできない。

完全なプログラムに戻ってみよう。

ラベルの長さを計算したあと、main の中で2つの出力を組み合わせる。I/Oの順序を持つEffectの合成として、ここでは do が自然に読める。

chapter-label-lengths.ssrg / 完全なプログラム
Playgroundで動かす ↗
import * as text from "std/text"

let labels = [" Build ", "bundle", "CHECK", "run"]
let lengths = map (\label -> text.lengthScalars (text.trim label)) labels
let total = reduce 0 (+) lengths

pub effect fn main = do {
  println (show lengths)
  println (show total)
}

同じEffect値を二度実行したら、その計算も二度実行される。Effectはcoldだからだ。逆に、先に作られた計算を自動的に実行したり、Promiseのようなeagerな振る舞いを前提にしたりはしない。

依存している計算、独立した計算。

>>= は前の結果で次の計算を決められる。<*> は、次の計算の形が前の結果に依存しない場合のApplicativeな合成。**どちらを使うかと、必ず並列になるかどうかは別の話**で、具体的な実行順序は型とinstanceに従う。

一番大事なのは、Seseragiが純粋な値計算と、外の世界に触れる計算の境界を曖昧にしないこと。型と式が、その違いをちゃんと表してくれる。

別の章へ進む前に

<$>・<*>・>>= の違いは、関数の合成の記事でも図で確認できる。この章の内容はここだけで読めるように、引き続き本文を磨いていく。
