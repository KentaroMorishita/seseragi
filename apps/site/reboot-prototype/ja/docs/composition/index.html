03 / COMPOSITION

関数を組み合わせる

合成にはいくつも書き方がある。 |> だけが答えではない。どこから読むと自然か、どんな値を扱っているかで選んでみよう。

同じ処理を、違う記法で。

候補を検索して、その結果に表示用の badge を付ける。短くするために検索条件を pick へ切り出した。残る3行は同じ結果になる。わざと全部を一つの記法へ揃える必要はない。

syntax-reader-pipelines.ssrg
Playgroundで試す ↗ 
let pick = arrays.filter (matches "b")
let nested = map badge (pick commands)
let compact = map badge $ pick commands
let choices = commands |> pick |> map badge

通常適用は関数の入れ子。 $ は右側の式をまとめて左に渡す。 |> は値から処理の流れを左から追える。 違いは、見せたい構造 なんだ。

見つからない結果は、消さなくていい。

arrays.find は候補が無い場合もある。その結果に無理やり badge を適用する代わりに、 <$> を使える。

find-and-map.ssrg
Playgroundで試す ↗ 
let picked = arrays.find (matches "b") commands
let suggestion = badge <$> picked
let missing = arrays.find (matches "z") commands
let absentLabel = badge <$> missing

badge <$> picked は、値があれば badge を適用し、無ければ不在のままにする。ここでは <$> の意味があるから使っている。

全部の書き方をPlaygroundで比較する ↗ 記法だけを調べる →
演算子の役割を並べて見る

$ は低優先順位の適用、 |> はパイプ、 <$> は文脈のある値への写像。 <*> ・ >>= ・ do は別の合成を扱う。記号は見た目ではなく意味で選ぼう。
