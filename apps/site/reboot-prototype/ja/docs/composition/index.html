Guide / 関数の合成
03 / COMPOSITION & CONTEXT

関数の形より、値の流れを見よう。

Seseragiには $、|>、<$>、<*>、>>= といった記法がある。でも、記号を全部覚えて使うことが目的じゃない。何を合成しているのかによって、書き方の意味が変わるところが面白い。

まず、ただの関数適用。

コマンド名の検索を続けよう。検索した候補に、画面表示用の badge を付ける。ここで扱うのは、まだ通常の関数と配列だ。

01 / 抜粋：同じ結果を3通りで
fn badge name: String -> String = "> " + key name

let nested = map badge (arrays.filter (matches "b") commands)
let compact = map badge $ arrays.filter (matches "b") commands
let choices = commands |> arrays.filter (matches "b") |> map badge

3つは同じ結果になる。ただし「どれが一番短いか」を競っているわけじゃない。map badge (…) は関数の入れ子をそのまま読む。$ は右側の式をまとめて渡すための低優先順位の適用。|> は値が左から右へ渡っていく順番を示す。どれも通常の関数適用を表せるけれど、見せたい構造が違う。

たとえば右側に if や match が続くなら、$ で括弧を減らせることがある。処理の流れを追いたいなら |> が読みやすい。でも毎回無理にパイプを作る必要はない。

値が「あるかもしれない」とき。

次は検索結果が一件だけ欲しいとき。arrays.find は候補が見つからない可能性を Maybe<String> という型で表す。String を受け取る badge に、そのまま Maybe<String> を渡すことはできない。

02 / 抜粋：Maybeを保ったまま変換する
let picked = arrays.find (matches "b") commands
let suggestion = badge <$> picked

let missing = badge <$> arrays.find (matches "z") commands

ここでの <$> は、「値が入っていたら中身へ関数を適用し、外側の文脈は保つ」という操作。一般にはFunctorの map に相当する。配列への変換と似た顔をしているけど、何を保つかは型構築子によって違う。

では、ほかの記号は何を表す？

THREE DIFFERENT QUESTIONS
<$>
中身を変えたい。 F<A> に A → B の関数を適用し、F<B> にする。
<*>
別々の文脈付き引数を合わせたい。 Applicativeの適用。入力同士の依存関係を必要としない。
>>=
前の結果を見て、次の計算を決めたい。 Monadのbind。次の計算が前の値に依存する。

ここでの「独立」は、必ず並列実行するという意味ではない。どんな順序・効果を持つかは、その型とinstanceの意味に従う。

do は >>= による合成を読みやすく書く記法。Effect専用というわけではない。この違いを知っておくと、処理や失敗を扱う章で急に別物が出てきたようには感じなくなるはず。

完全なコードで確かめる。

ここまでの抜粋には key や commands の定義が省略されている。実行できるプログラム全体では、3つの通常の書き方が同じ結果になることと、Maybe に <$> を使うとどうなるかを両方試せる。

syntax-reader-pipelines.ssrg / 完全なプログラム
Playgroundで動かす ↗
import * as text from "std/text"
import * as arrays from "std/array"

fn key name: String -> String = name |> text.trim |> text.toLower
fn matches query: String -> name: String -> Bool =
  text.startsWith (key query) (key name)
fn badge name: String -> String = "> " + key name

let commands = [" Build ", "bundle", "CHECK", "run"]
let nested = map badge (arrays.filter (matches "b") commands)
let compact = map badge $ arrays.filter (matches "b") commands
let choices = commands |> arrays.filter (matches "b") |> map badge
let same = nested == compact && compact == choices
let picked = arrays.find (matches "b") commands
let suggestion = badge <$> picked
let missing = badge <$> arrays.find (matches "z") commands

pub effect fn main = do {
  println (show choices)
  println (show same)
  println (show suggestion)
  println (show missing)
}
少し数学の寄り道：Functorの法則

Functorのmapは好き勝手に変換できるわけじゃない。同じ値を返す関数を写しても元の文脈が変わらないこと、関数を合成してから写すのと順に写すのが一致することが大切だ。だから <$> は単なる省略記号ではなく、型をまたいで使える意味を持った操作になる。
