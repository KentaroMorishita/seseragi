Guide / Composition
03 / COMPOSITION & CONTEXT

Follow the value, not just the punctuation.

Seseragi gives you $, |>, <$>, <*> and >>=. The goal isn't to use every symbol. Each one lets you express something about the kind of composition you're doing.

Start with ordinary function application.

Take our command search. Once we've selected matching commands, we want to give them a label for display. We're still working with plain functions and an array.

01 / Excerpt: three ways to express the same result
fn badge name: String -> String = "> " + key name

let nested = map badge (arrays.filter (matches "b") commands)
let compact = map badge $ arrays.filter (matches "b") commands
let choices = commands |> arrays.filter (matches "b") |> map badge

All three produce the same result. The point isn't which one uses fewer characters. map badge (…) makes nesting explicit. $ groups the expression on the right for application. |> reads as a value travelling through transformations from left to right. These describe ordinary application with different reading directions.

If an if or match follows, $ can help avoid extra parentheses. If a sequence of transformations is what matters, a pipeline may read better. Neither spelling needs to be forced onto every line.

Now the result might be missing.

Suppose we want one matching command. arrays.find represents the possibility of no result as Maybe<String>. Our badge function expects String, so we can't simply apply it to a Maybe value.

02 / Excerpt: transform inside Maybe
let picked = arrays.find (matches "b") commands
let suggestion = badge <$> picked

let missing = badge <$> arrays.find (matches "z") commands

<$> maps a function over a value inside a context, keeping that context intact. This is the Functor map operation. The similarity to mapping over an array is useful, but what gets preserved depends on the type constructor involved.

So what about the other symbols?

THREE DIFFERENT QUESTIONS
<$>
Transform what is inside. Map an A → B function over F<A> to get F<B>.
<*>
Combine context-bearing inputs. Applicative application does not need one input to decide what the next computation will be.
>>=
Choose the next computation from the previous result. Monad bind expresses value-dependent composition.

Independent inputs do not imply automatic parallel execution. Scheduling and effects depend on the type and its instance.

do is syntax for reading Monad-style composition. It is not exclusive to Effect. Keeping that distinction in mind will make effects and typed failures easier to understand in the next chapter.

Try the complete program.

The earlier excerpts left out definitions such as key and commands. This runnable program lets you compare the three ordinary forms and map into a Maybe result.

Run in Playground ↗
import * as text from "std/text"
import * as arrays from "std/array"

fn key name: String -> String = name |> text.trim |> text.toLower
fn matches query: String -> name: String -> Bool =
  text.startsWith (key query) (key name)
fn badge name: String -> String = "> " + key name

let commands = [" Build ", "bundle", "CHECK", "run"]
let nested = map badge (arrays.filter (matches "b") commands)
let compact = map badge $ arrays.filter (matches "b") commands
let choices = commands |> arrays.filter (matches "b") |> map badge
let same = nested == compact && compact == choices
let picked = arrays.find (matches "b") commands
let suggestion = badge <$> picked
let missing = badge <$> arrays.find (matches "z") commands

pub effect fn main = do {
  println (show choices)
  println (show same)
  println (show suggestion)
  println (show missing)
}
A mathematical detour: Functor laws

Functor mapping obeys useful laws. Mapping the identity function changes nothing. Mapping a composed function is equivalent to mapping its parts in sequence. That's why <$> carries a reliable meaning rather than being mere punctuation.
