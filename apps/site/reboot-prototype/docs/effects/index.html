Guide / Effect and do
04 / VALUES, EFFECTS, EXECUTION

Describing a computation isn't running it.

Calculating a value is different from reading a file, printing a line, or making a network request. Seseragi represents computations that interact with the outside world as Effect values. That lets us compose a plan before running it.

A pure calculation needs no outside world.

Suppose we trim the edges of some labels, count their characters, and add the lengths. The result depends only on the strings in our array.

01 / Excerpt: calculate values
let labels = [" Build ", "bundle", "CHECK", "run"]
let lengths = map (\label -> text.lengthScalars (text.trim label)) labels
let total = reduce 0 (+) lengths

map gives us [5, 6, 5, 3]; reduce adds them to 19. No console, filesystem or network is required just to compute that value.

What changes when we want to print?

Calculating a number and writing that number to a console aren't the same kind of operation. println describes an operation requiring the console environment; it does not expose I/O as a plain pure function returning an ordinary Unit.

In Effect<R,E,A>, R describes the required environment, E the recoverable failure channel, and A the success value. Those are part of the type, not conventions hidden in comments.

The application's pub effect fn main provides the entry-point Effect. Merely declaring an effect fn doesn't run an operation.

do belongs to Monad, not only to Effect.

It's worth getting this exactly right. do is readable syntax for a sequence of Monad binds. It is not reserved for Effect or Task, and it is not a way of turning ordinary expressions back into imperative statements.

THE MEANING OF DO
Written with do
do {
  x <- mx
  next x
}
≡
Expressed with bind
mx >>= (\x -> next x)

Think of mx as an M<A> value, and next as a function from the unwrapped A to the next M<B>. This diagram shows the semantic expansion, not a stand-alone runnable program.

Inside do, x <- mx binds a value, while let x = ... introduces a pure local name. The final expression is required and has the same Monad constructor. Different Monads aren't implicitly mixed.

Here's the complete program.

After calculating the lengths, the Effect returned by main combines two output operations. Sequencing them with do reads naturally in this example.

chapter-label-lengths.ssrg / complete program
Run in Playground ↗
import * as text from "std/text"

let labels = [" Build ", "bundle", "CHECK", "run"]
let lengths = map (\label -> text.lengthScalars (text.trim label)) labels
let total = reduce 0 (+) lengths

pub effect fn main = do {
  println (show lengths)
  println (show total)
}

If you execute the same Effect twice, its computation is performed twice. The value is cold. You shouldn't assume a Promise-like eager start, or that simply constructing an Effect performs I/O.

Dependent and independent computations differ.

>>= allows the next computation to depend on a previous result. Applicative <*> combines computations without making the form of the next one depend on that value. This does not automatically mean parallel execution; runtime behavior follows the relevant type and instance.

The key is that Seseragi doesn't blur the boundary between a value calculation and interaction with the outside world. Its types and expressions make that boundary visible.
