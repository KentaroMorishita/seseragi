01 / FUNCTION APPLICATION

Functions and notation

Write small functions first. Compose them when the task calls for it. A function can itself become a value — even after some arguments have already been supplied.

A small function is a useful promise.

Need to trim a label and normalize its casing? Give that little job a name.

functions.ssrg
Try in Playground ↗ 
import * as text from "std/text"

fn key name: String -> String = text.toLower (text.trim name)

fn declares a function. name: String is the input, and the last String is the result type. The expression after = is the result — no return statement needed.

Pass a value by writing it after the function.

key " Build " applies the function to a string. You are not building a parenthesized argument list.

Supply some arguments. Keep the function.

This one checks whether a command starts with a query. The query can be supplied now and the command later.

function-values.ssrg
Try in Playground ↗ 
fn matches query: String -> name: String -> Bool =
  text.startsWith (key query) (key name)

let builds = matches "b"
let choices = arrays.filter builds commands

matches "b" is still a function, waiting for a name. filter can use it without having to know how that function was made.

Function application, precisely

fn f x: A -> B = ... declares parameter and result types. f value applies a function. When arguments remain, the result is another function value.
