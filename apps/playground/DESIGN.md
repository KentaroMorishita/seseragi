# Playground / Tour デザインの決めごと（v2）

Playground と Tour の画面を作り直す人のための文書です。見た目、言葉、操作の感触をそろえるための決めごとをまとめます。

- 何をどこに置くか（画面の役割と導線）は [`INFORMATION_ARCHITECTURE.md`](./INFORMATION_ARCHITECTURE.md) が決めます。この文書の形に合わせて、画面を作り直すときに直します（#1358、#1359）。
- この文書は #1350 で決まりました。画面の作り直しは、共通部品とデザイントークン（#1357）、Playground（#1358）、Tour（#1359）、日本語と英語の切り替え（#1360）の順に進めます。
- トークンと共通部品の実装は [`src/ui/design/`](./src/ui/design/) にあります。部品の見本は、開発サーバーの `/ui-kit.html` で、ライトとダークを切り替えて見られます。
- 画面案の静的モックは [`docs/design/playground/mock/`](../../docs/design/playground/mock/index.html) にあります。自由に書く状態とエディターの支援は `write.html`、案内を畳んだ通常状態は `playground.html#quiet` です。モックは決める前の資料なので、数値や言い回しがこの文書と違うときは、この文書に従います。
- 旧案（現行レイアウトを整理した案）は [`docs/design/playground/archive/v1/`](../../docs/design/playground/archive/v1/) に残しています。この文書は旧案を前提にしません。

## 1. アートディレクション「澄んだ流れ」

今の画面は、暗い緑一色の IDE に見えます。初めて来た人には「道具箱」に見え、触る前に身構えさせます。v2 は骨格から作り直し、次の三つの言葉で見た目を決めます。

| 言葉 | 画面での形 |
| --- | --- |
| 澄んでいる | 明るいキャンバスに白いカードを浮かべる。線は細く、余白は広く、色は最小限にする |
| 流れる | コード → 実行 → 出力の流れを、画面の形そのものにする。Run ボタンは二つのカードをつなぐ流れの上に置く |
| 手ざわりがある | 書き換える場所を指すひとこと、押すと試せる Try next のチップ、終わると付くチェックなど、触ると返事がある |

この方向を選んだ理由は次のとおりです。

- **名前とつながる。** Seseragi は「せせらぎ」です。パイプライン（`|>`）で値が流れる言語でもあります。流れを画面の骨格にすると、言語の性格がそのまま伝わります。
- **ブランドの色を主役にする。** アクセントはロゴと同じティール（`#009aad` → `#00b4b8`）です。今のミントグリーンはロゴと合っていません。
- **開発者向けプロダクトの水準に合わせる。** Linear や Vercel のような精度（細い線、そろった文字、少ない色）を土台にして、そのうえで触って楽しい動きを足します。
- **ライトとダークの両方を最初から作る。** 既定は OS の設定に合わせます。docs サイトは既定がダークなので、行き来しても違和感がないよう、ダークも同じ水準で作ります。

## 2. 体験の原則

### 開いた瞬間に、動くコードと結果が見える

- 最初の例は、`type`・`match`・`|>` が一度に見える 10 行前後のコードにします。開いたときに一度だけ自動で実行し、結果を最初から見せます。
- モバイルでも、コードと結果の頭（最初の数行）を同時に見せます。結果は下から出るシートに出し、最初から少しだけ顔を出しておきます。

### 自由に書くことも、初回と同じ重さで扱う

- Playground の目的は二つあります。用意した例を動かして知ること、そして白紙から書いたり、よそから貼り付けたりしたコードを動かして遊ぶことです。後者を「自由に書く」状態と呼び、初回の体験と同じ重さで設計します。
- 次のときは、自由に書く状態で開きます。
  - New file（`⌘N`）で白紙から始めたとき
  - 貼り付けで、コード全体を置き換えたとき
  - `?source=` 付きのリンクで開いたとき
  - 2 回目以降に、前回のコードが戻ってきたとき
- この状態では案内を一切出しません。見えるのは、コード、Run、出力、エディターの支援（エラー、型のホバー、補完）だけです。
- 自分のコードは自動では実行しません。Run（`⌘↵`）を押したときだけ実行します。
- 書いたコードはこのブラウザに自動で保存し、下の帯に `Saved in this browser` と出します。

### 案内は初回だけ、消せて、ふだんは静か

初めての人に向けた案内は、次の決まりで出します。どれも閉じたことをこのブラウザに保存し、同じ案内を二度押し付けません。

| 案内 | 出すとき | 消し方 | 消したあと |
| --- | --- | --- | --- |
| English is available の帯 | ブラウザの言語が日本語でない人が、初めて `/` を開いたとき | `×` | 二度と出さない |
| 書き換える場所を指すひとこと | 初めて開いた、最初の例だけ | Close を押す、コードを書き換える、Run を押す、のどれか | 二度と出さない |
| Try next のチップ | 用意した例を開いたとき | Hide | `Try next` と数と Show だけの一行に畳む。自由に書く状態では、この一行も出さない |
| 開いたときの自動実行 | 用意した例を開いたとき | — | 自由に書く状態では、自動で実行しない |

- Search の Settings に `Hints` の切り替えを置きます。オフにすると、ひとことも Try next も出しません。オンに戻すと、ひとことをもう一度出せます。
- 案内を閉じた記録は、言語のように URL には入れません。人ではなく、このブラウザについての記録だからです。
- Tour は案内そのものが本文なので、この決まりの対象外です。

### 主役は Run

- Run（実行）ボタンは画面に一つだけの、一番強いボタンです。デスクトップではコードと出力の間の流れの上に、モバイルでは右下に浮かべて置きます。
- ほかの操作は、控えめなボタンかチップで見せます。

### 探す場所は一つ

- 例、Tour のレッスン、API、設定は、すべて Search（`⌘K`）から見つけます。
- 今ある「例を探す」「Reference」「Settings」のダイアログは、この一つにまとめます。

### 切り替えは、いつも見える

- Playground と Tour の切り替え、日本語と英語の切り替えは、上のバーに常に出します。メニューの中に入れません。

### 言葉は読み手に合わせる

- 読み手は、TypeScript を普通に書けるエンジニアです。
- UI ラベル（ボタン、タブ、見出し、状態）と開発用語は、日本語の画面でも英語のまま出します。Run、Format、Output、Console のような開発者の共通語彙を日本語に置き換えると、かえって分かりにくくなるためです。
- 案内や説明の文章（ひとこと、レッスンの本文、手順、例の説明、目次の説明）は日本語で書きます。
- プロジェクトの中だけで通じる名前は出しません。設計文書の分類名（Recipe、Showcase、surface、facet）と、実装の名前（registry、manifest、canonical）がこれに当たります。
- 言語のキーワードと型名（`fn`、`match`、`Int`、`Effect`、`Signal`）、固有名の Seseragi、Playground、Tour はそのまま使います。
- 線の引き方と言葉の一覧は「6. 日本語と英語」の「画面の言葉」にまとめます。

### 狭い画面では、削らずに重ねる

- 上は二段までにします。入りきらないものは、消さずにシートや浮かぶボタンへ移します。
- 例の名前、レッスンの現在地、言語の切り替えは、狭い画面でも必ず見せます。

### 支援機能は落とさない

- 今の Playground と Tour は、書いている途中のエラー表示、型のホバー、複数ファイル、検索と置換などの支援を持っています。見た目を作り直しても、これらは一つも落としません。
- 置き場所は「3. 画面の骨格」の「エディターの支援」に表でまとめます。

### 失敗はやさしく

- エラーは、コードの該当行と出力の両方に出します。
- 書き換えた内容を、確認なしで消しません。

## 3. 画面の骨格

### 共通: 上のバー

上のバーは三つに分けます。

| 左 | 中央 | 右 |
| --- | --- | --- |
| ロゴ、Seseragi、バージョン | Playground / Tour の切り替え | Search（`⌘K`）、テーマ、言語（JA / EN） |

- 背景は付けず、キャンバスの上に直接置きます。
- Run ボタンは上のバーに置きません。

### Playground

```
┌ 上のバー ───────────────────────────────────────────────┐
│ ┌ コードのカード ───────────┐  流  ┌ 出力のカード ─────────┐ │
│ │ 例の名前 ▾  main.ssrg      │  れ  │ Output [Console|Preview] │ │
│ │                            │  ▶  │ › 結果                  │ │
│ │ （ひとこと）               │ Run  │                         │ │
│ │                            │  ┆  │ Try next: [チップ]…     │ │
│ └────────────────────────────┘      └─────────────────────────┘ │
└ ● Ready · Docs · GitHub ──────────────────────────────────┘
```

- コードのカードの見出しには、例の名前（押すと Search が例の一覧で開く）、ファイル名、Guide（例の解説）、Format、Reset を置きます。
- 初めて開いたときだけ、書き換える場所を指すひとこと（コーチマーク）を出します。書くのは「何を変えるか」と「Tour への入口」だけです。
- 出力のカードには、結果の行、状態（`✓ 18 ms`）、Try next のチップを置きます。チップを押すと、その書き換えがコードに入ります。チップの中身は「雨量を 12mm にする」のような日本語の文です。
- 2 回目からは、案内を畳んだ通常状態で開きます。ひとことと自動実行の知らせは出さず、Try next は一行に畳みます（モックの `playground.html#quiet`）。

自由に書く状態（モックの `write.html`）では、カードの中身が次のように変わります。

```
┌ code ──────────────────────────────────┐      ┌ output ─────────────────────────────┐
│ [F] Untitled v  main.ssrg  +   Format │      │ Output  Console Preview Problems(1) │
│ 13    |> map (\item -> item.price)     │  >   │ ERROR SES-T0101     main.ssrg:14:20 │
│ *14   |> map (discount "10")           │ Run  │ Argument type does not match ...    │
│                        ~~~~            │      │ Expected Int / Actual String        │
└────────────────────────────────────────┘      └─────────────────────────────────────┘
* 1 error · Ln 14, Col 20 · Saved in this browser · Docs · GitHub
```

（`[F]` は Files のアイコン、`*` はエラーの点、`~~~~` は波線です。）

- 例の名前の代わりに `Untitled`（自分でつけた名前があればそれ）を出します。押すと、今と同じく Search が例の一覧で開きます。
- ひとことと Try next は出しません。出力のカードは、結果か Problems だけです。

### Tour

```
┌ 上のバー ──────────────────────────────────────────────┐
│ Contents  第1章 · はじめの一歩 ▬▬▭▭ 1/24 │ ┌ コード ────────┐ │
│                                         │ └────────────────┘ │
│ 最初のプログラムを動かす（題名）       │    ┄┄ ▶ Run ┄┄     │
│ 一文の導入                              │ ┌ Output ────────┐ │
│ ┌ Try it ───────────────┐               │ │ ✓ 期待どおり   │ │
│ └───────────────────────┘               │ └────────────────┘ │
│ Walkthrough ①②  /  Going further（折りたたみ）                │
│ ┌ Next: 次のレッスン名 → ┐              │                    │
└─────────────────────────────────────────┴────────────────────┘
```

- 左はレッスンの読み物です。本文はカードに入れず、キャンバスに直接置きます。Try it（自分で書き換える手順）だけをカードにして目立たせます。
- Walkthrough（コードの読み解き）の番号（①②）は、エディターの中にも同じ番号のピンとして出し、どこの話かを示します。
- 右は、コード・実行・出力を縦に並べます。Playground と同じ部品を、向きだけ変えて使います。
- 章の中の進み具合は、レッスンの数だけ区切ったバーで見せます。
- 目次（Contents）はコースマップにします。章をカードで並べ、進み具合と現在地（Current）を見せます。開いても上のバーは残します。

### モバイル（760px 以下）

| 段 | Playground | Tour |
| --- | --- | --- |
| 1 段目 | ロゴ、Playground / Tour、Search、JA / EN | 同じ |
| 2 段目 | 例の名前 ▾、Format、More | Contents、章の名前、区切りのバー、1/24 |
| 本体 | コード。下から出力のシートが顔を出す | レッスン。下の Lesson / Code で切り替える |
| 浮かぶもの | 右下に Run ボタン | コードを開いたときだけ、右下に Run ボタン |

- 出力のシートは三段で止まります。最初は 196px だけ顔を出し、引き上げると画面の 7 割まで広がります（Run のあとも 7 割）。下まで払うと、持ち手と出力の見出しだけを残して畳み、エディターを広く使えます。持ち手のタップは、7 割と 196px を行き来し、畳んでいるときは 196px に戻します。
- ひとこと（コーチマーク）は、コードに重ねず、コードの上に置きます。

### エディターの支援（今ある機能の置き場所）

今の Playground と Tour が持っている支援機能を、新しい骨格のどこに出すかを決めます。Tour のコードと出力も同じ部品なので、エラー、ホバー、補完は Playground と同じ形で出します。

| 機能 | 今の形 | v2 の置き場所 | モバイル |
| --- | --- | --- | --- |
| 書いている途中のエラーと警告 | 入力が止まって 240ms 後に解析する。該当箇所に下線、行番号の横に印、出力にエラーのカード、下の帯に件数 | コードでは波線と、行番号の横の点（エラーは `--error`、警告は `--warn`、情報は `--accent-ink`）。行の背景もうっすら色を付ける。指すと吹き出しで、コード（`SES-T0101`）、メッセージ、Expected / Actual を出す | 同じ。吹き出しはタップで出し、見えている範囲に収める |
| エラーのカード | コード、メッセージ、場所（押すとその位置へ移る）、Expected / Actual、型の差分、ラベル、Help、Fix、Note | 出力のカードの `Problems` タブに、件数のバッジを付けて並べる。Run したときにエラーがあれば Problems を開く。中身の項目は今と同じで、一つも削らない | 出力のシートの頭に Problems と件数。場所を押すと、シートを下げて該当行へ移る |
| 型のホバー | 識別子や式を指すと、色付きのシグネチャ、Inferred（推論した型）、Remaining（部分適用で残る引数）、`where` の制約、モジュール、説明を出す | 指した文字の上に白い吹き出し。一行目に色付きのシグネチャ、続けてラベル付きの行。指している範囲は薄いティールで示す | タップで出す（今と同じ）。見えている範囲に収める |
| 補完 | **今はない。** 解析は、その位置で期待される型とレコードのフィールドを返しているが、エディターでは使っていない | 新しく入れる案。カーソルの下に一覧を出す。種類のアイコン、名前、型を並べ、下に選んだ候補のシグネチャとキーの案内（`↵` Insert、`esc` Close）を置く | 一覧は 4 行まで。キーボードの上に出す |
| 編集の操作 | 複数カーソル、矩形選択、取り消し、括弧を閉じる、対応する括弧の強調、自動インデント、折りたたみ、検索と置換（`⌘F` / `⌘H`）、選択と同じ語の強調、行コメント（`⌘/`）、行の移動（`⌥↑` / `⌥↓`）、Tab でインデント、空白の表示 | すべて残す。検索と置換は、コードのカードの見出しのすぐ下に細い帯で出す | 検索と置換は More から開く |
| Format | 共通のフォーマッター。エラーがあると整形せず、エラーを出す | コードのカードの見出し。整形できなかったときは Problems に出す | 2 段目 |
| 複数のファイル | Explorer（ファイルとフォルダーの作成、名前の変更、削除、入口のファイル）とタブ | 見出しのフォルダーのアイコンで、Explorer をカードの左側に開く。ファイルはタブで切り替え、`+` で足す。保存していない変更はタブに点で示す | 2 段目のフォルダーのアイコンから、下のシートで開く |
| 入力（stdin） | 出力側の Input 欄 | 出力のカードの見出しの `Input` で、結果の上に入力欄を開く | More から |
| Preview と全画面 | Text / Preview の切り替えと全画面 | `Console` / `Preview` の切り替え。Preview のときだけ全画面のボタンを出す | 同じ |
| 出力を消す | Clear | 出力のカードの見出しのごみ箱 | More から |
| 解析の状態 | 下の帯に `Analyzing…`、`Analysis ready`、件数 | 下の帯に `Ready` か件数、カーソルの位置、保存の状態。状態のチップにも件数を出す | 状態のチップ |
| 保存と共有のリンク | ブラウザに自動で保存。`?source=` のリンクは、前の作業を上書きしない別の保存先で開く | 同じ。下の帯に `Saved in this browser` | 同じ |
| キーボード | `⌘↵` で実行、`F6` / `⇧F6` で領域を移る、`⇧⌘E` で Explorer | 同じ。Search から一覧を見られるようにする | — |
| API の一覧 | Reference のダイアログ（解析が返す標準ライブラリ） | Search の API | 同じ |
| Interop と Convert bindings | `seseragi.toml` で設定したときだけ出る | 同じ条件で、コードのカードの More に入れる | More から |
| エディターの設定 | 空白の表示（Show indentation whitespace）、フォーマッターの行幅 | Search の Settings | 同じ |

- エラーやホバーの中の文（コンパイラのメッセージ、型）は、英語の原文のまま出します（「6. 日本語と英語」の 5 段目）。
- 補完は今の機能ではありません。入れるかどうかと時期は、この文書とは別に決めます。置き場所だけ先に決めておき、入れるときに見た目がぶれないようにします。

### Search（`⌘K`）

- 入力欄、範囲のチップ（All、Examples、Lessons、API、Settings）、結果の一覧、キーの案内の順に並べます。
- 結果は種類ごとにまとめ、左のアイコンの形と色で種類を見分けられるようにします。結果の題名と説明は日本語です。
- New file（白紙から書く）、最初の例に戻る、テーマ、文字の大きさも、ここから選べるようにします。
- モバイルでは、下から出るシートにします。

## 4. デザイントークン

トークンは CSS のカスタムプロパティとして `:root` に一か所で定義し、ダークはその上書きだけで作ります。実装は [`src/ui/design/tokens.css`](./src/ui/design/tokens.css) です。

- テーマの既定は OS の設定（`prefers-color-scheme`）に合わせます。
- 選んだテーマ（System / Light / Dark）はこのブラウザに保存し、`<html data-theme>` として OS の設定より優先します。保存した選択は、ページを描く前に当てて、開いた瞬間に色がちらつかないようにします（[`src/ui/theme.ts`](./src/ui/theme.ts)）。
- 部品の CSS には色や影の値を直接書かず、トークンだけを使います。

### 動き

- 時間は 160〜220ms、曲線は `cubic-bezier(0.2, 0.8, 0.2, 1)` にそろえます。
- 実行すると、流れの線に沿って点が流れ、出力の行が上から順に現れます（1 行 60ms ずつ遅らせる）。
- `prefers-reduced-motion` が有効なら、動きをすべて止めます。

## 6. 日本語と英語

### 切り替えの置き場所

- 上のバーの右端に `JA` / `EN` を置きます。デスクトップでもモバイルでも同じ位置です。
- メニューの中には入れません。docs サイトでは、モバイルで言語の切り替えがメニューの中に隠れることが指摘されています（seseragi-docs #38 の 5）。

### どう覚えておくか

- 言語は URL のパスで表します。docs サイトと同じく、日本語は `/`、`/tour/`、英語は `/en/`、`/en/tour/` です。
- 切り替えても、今の場所は保ちます。開いている例、レッスン、書き換えたコード、出力はそのまま残します。
- 保存した好みで、別の言語のページへ自動で移動はしません。共有したリンクの言語が、開く人によって変わらないようにするためです。
- `/` を開いた人のブラウザの言語が日本語でないときは、一度だけ「English is available」の帯を出します。閉じたら、このブラウザでは二度と出しません。

### 何を訳すか

| 段 | 対象 | 英語版を出す時点での扱い |
| --- | --- | --- |
| 1. 画面の部品 | ラベル（ボタン、タブ、見出し、状態、タグ）と、画面に固定の案内文（自動で実行した知らせ、未訳の案内、目次の説明など） | ラベルは日本語の画面でも英語なので、訳す作業はない。固定の案内文はすべて訳しておき、未訳のまま出さない |
| 2. 名前と短い文 | 例・章・レッスンの題名、一行の説明、例ごとのひとことと Try next のチップ | 先に訳す。未訳なら日本語で出し、`Japanese only` の印を付ける |
| 3. 本文 | レッスンの本文と手順、例の解説、設計の背景の記事 | 未訳なら日本語の原文を出し、本文の先頭に一行の案内を置く |
| 4. コード | 例やレッスンのコードの中の文字列とコメント | 英語版のコードがあればそれを出す。なければ日本語版。キーワードと名前は訳さない。期待する出力は、出したコードに合わせる |
| 5. コンパイラのメッセージ | エラーや警告の本文 | 今は英語だけ。どちらの言語でも原文のまま出す。件数の表示（`1 error` など）もラベルなので英語 |

### 未翻訳のものの扱い

- 未訳のものを隠しません。Tour の順番が崩れ、例の数が言語で変わってしまうためです。
- 未訳の本文には `lang="ja"` を付け、読み上げが日本語で読めるようにします。
- 案内の文は「This lesson isn't translated yet. Its text is shown in the original Japanese. Buttons, code, and output work the same.」のように、何が未訳で何は変わらないかを一文ずつ書きます。
- 機械翻訳を自動で出しません。
- 英語では文字の幅が変わります。ボタンやチップは幅を固定せず、中身に合わせて伸ばします。

### 画面の言葉

日本語の画面でも、UI ラベルと開発用語は英語のまま出します。日本語で書くのは、案内や説明の文章です。

| 種類 | 日本語の画面 | 例 |
| --- | --- | --- |
| UI ラベル（ボタン、タブ、切り替え、見出し、状態、範囲のチップ、タグ、件数） | 英語 | Run、Format、Output、Try it、Featured、`3 lessons` |
| 開発用語（文の中に出るときも） | 英語 | Run、Output、Preview、API |
| 中身の名前（例・章・レッスンの題名） | 日本語 | 天気のアドバイス、第1章 · はじめの一歩 |
| 案内や説明の文章 | 日本語 | 「3 を 12 に変えて、Run を押してみましょう。」、Try next のチップ、レッスンの本文と手順、目次の説明 |
| コンパイラのメッセージ | 英語（原文のまま） | `error[SES-T0101]: Argument type does not match the parameter type` |

見分け方は次のとおりです。

- どの例やレッスンでも同じ文字列で、押すもの・選ぶもの・区画の名前なら、ラベルです。英語にします。
- 例やレッスンごとに中身が変わるもの、一文として読ませるものは、文章です。日本語にします。Try next のチップは押すものですが、例ごとの書き換えの提案なので文章として扱います。
- 文の中で画面の部品を指すときは、ラベルと同じ英語で書きます（「Run を押す」「Output に出ます」）。ラベルと本文で呼び名を変えないためです。
- `aria-label` は、見えているラベルと同じ英語にします。見た目と読み上げの名前を一致させるためです。例外は言語の切り替えで、「日本語」「English」とそれぞれの言語で書きます。

## 7. レイアウトと画面幅

| 幅 | Playground | Tour |
| --- | --- | --- |
| 1101px 以上 | コード 1.25 : 流れ 104px : 出力 1 | レッスン 440〜560px と、コード・実行・出力の縦並び |
| 761〜1100px | コード 1 : 流れ 88px : 出力 0.9。Search は虫めがねだけ | レッスンとラボを 1 : 1 |
| 760px 以下 | 「3. 画面の骨格」のモバイルの表 | 同じ |

- 画面幅による切り替えは、CSS ファイルの末尾の一か所にまとめます。
- モバイルのコードは横にスクロールさせず、行番号の幅だけ字下げして折り返します。docs サイトのコードブロックは横スクロールにする案が出ています（seseragi-docs #38 の 2）。エディターと読み物で方針を分けるかは、実装のときに決め直します。
- iOS のホームバーなどに隠れないよう、`env(safe-area-inset-*)` を余白に足します。

## 8. アクセシビリティ

- 文字と背景のコントラストは、ライトとダークの両方で 4.5:1 以上にします。
- キーボードで操作したときは、2px のアクセント色の枠でフォーカスを見せます。
- 色だけで状態を伝えません。成功には ✓、現在地には `Current` や番号を、文字と一緒に出します。
- 押せる領域は 36px 以上、タッチ操作では 44px 以上にします。
- 出力と状態のチップは `aria-live="polite"` で読み上げます。Problems の件数も同じです。
- エラーは波線の色だけに頼りません。行番号の横の点、吹き出し、Problems の文字でも伝えます。
- ホバーの吹き出しは、キーボードでもカーソル位置から開けるようにします（今のタッチ操作と同じく、カーソル位置で出す）。

## 9. やらないこと

- 現行のレイアウト、色、部品を前提にした手直し。
- 内部の分類名や実装の説明を、画面の文言として出すこと。
- Run、Format、Output のような開発者の共通語彙を、日本語に置き換えること。
- Run 以外のボタンを、Run と同じ強さで目立たせること。
- Playground / Tour の切り替えや言語の切り替えを、メニューの中に入れること。
- 狭い画面で、ラベルや現在地を消すこと。
- 例、レッスン、API、設定ごとに別々の検索画面を作ること。
- 未訳のコンテンツを隠すこと。機械翻訳を自動で出すこと。
- トークンを通さずに、色や余白の値を直接書くこと。
- 書き換えた内容を、確認なしで消すこと。
- 自由に書いている人に、案内（ひとこと、Try next、帯）を出すこと。一度閉じた案内を、また出すこと。
- 見た目の作り直しを理由に、今ある支援機能（エラーの詳細、型のホバー、複数ファイル、検索と置換など）を削ること。
