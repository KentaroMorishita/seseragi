# Playground / Tour デザインの決めごと（v2 ドラフト）

Playground と Tour の画面を作り直す人のための文書です。見た目、言葉、操作の感触をそろえるための決めごとをまとめます。

- 何をどこに置くか（画面の役割と導線）は [`INFORMATION_ARCHITECTURE.md`](./INFORMATION_ARCHITECTURE.md) が決めます。この案を採用するときは、そちらも合わせて直します。
- 画面案の静的モックは [`design/mock/`](./design/mock/index.html) にあります。
- 旧案（現行レイアウトを整理した案）は [`design/archive/v1/`](./design/archive/v1/) に残しています。この文書は旧案を前提にしません。

> この版はドラフトです。数値や言い回しは、モックを見ながら決め直してかまいません。

## 1. アートディレクション「澄んだ流れ」

今の画面は、暗い緑一色の IDE に見えます。初めて来た人には「道具箱」に見え、触る前に身構えさせます。v2 は骨格から作り直し、次の三つの言葉で見た目を決めます。

| 言葉 | 画面での形 |
| --- | --- |
| 澄んでいる | 明るいキャンバスに白いカードを浮かべる。線は細く、余白は広く、色は最小限にする |
| 流れる | コード → 実行 → 出力の流れを、画面の形そのものにする。実行ボタンは二つのカードをつなぐ流れの上に置く |
| 手ざわりがある | 書き換える場所を指すひとこと、押すと試せる「次に試す」、終わると付くチェックなど、触ると返事がある |

この方向を選んだ理由は次のとおりです。

- **名前とつながる。** Seseragi は「せせらぎ」です。パイプライン（`|>`）で値が流れる言語でもあります。流れを画面の骨格にすると、言語の性格がそのまま伝わります。
- **ブランドの色を主役にする。** アクセントはロゴと同じティール（`#009aad` → `#00b4b8`）です。今のミントグリーンはロゴと合っていません。
- **開発者向けプロダクトの水準に合わせる。** Linear や Vercel のような精度（細い線、そろった文字、少ない色）を土台にして、そのうえで触って楽しい動きを足します。
- **ライトとダークの両方を最初から作る。** 既定は OS の設定に合わせます。docs サイトは既定がダークなので、行き来しても違和感がないよう、ダークも同じ水準で作ります。

## 2. 体験の原則

### 開いた瞬間に、動くコードと結果が見える

- 最初の例は、`type`・`match`・`|>` が一度に見える 10 行前後のコードにします。開いたときに一度だけ自動で実行し、結果を最初から見せます。
- モバイルでも、コードと結果の頭（最初の数行）を同時に見せます。結果は下から出るシートに出し、最初から少しだけ顔を出しておきます。

### 主役は「実行」

- 実行ボタンは画面に一つだけの、一番強いボタンです。デスクトップではコードと出力の間の流れの上に、モバイルでは右下に浮かべて置きます。
- ほかの操作は、控えめなボタンかチップで見せます。

### 探す場所は一つ

- 例、Tour のレッスン、API、設定は、すべて「探す」（`⌘K`）から見つけます。
- 今ある「例を探す」「Reference」「Settings」のダイアログは、この一つにまとめます。

### 切り替えは、いつも見える

- Playground と Tour の切り替え、日本語と英語の切り替えは、上のバーに常に出します。メニューの中に入れません。

### 内部用語を画面に出さない

- 画面の文言は、初めて来た人が読んで分かる言葉で書きます。
- 設計文書の分類名（Recipe、Showcase、surface、facet）、実装の名前（registry、manifest、canonical）、開発者向けの言葉（diagnostic、source、workspace）は出しません。
- 言語のキーワードと型名（`fn`、`match`、`Int`、`Effect`、`Signal`）、固有名の Seseragi、Playground、Tour はそのまま使います。

### 狭い画面では、削らずに重ねる

- 上は二段までにします。入りきらないものは、消さずにシートや浮かぶボタンへ移します。
- 例の名前、レッスンの現在地、言語の切り替えは、狭い画面でも必ず見せます。

### 失敗はやさしく

- エラーは、コードの該当行と出力の両方に出します。
- 書き換えた内容を、確認なしで消しません。

## 3. 画面の骨格

### 共通: 上のバー

上のバーは三つに分けます。

| 左 | 中央 | 右 |
| --- | --- | --- |
| ロゴ、Seseragi、バージョン | Playground / Tour の切り替え | 探す（`⌘K`）、テーマ、言語（JA / EN） |

- 背景は付けず、キャンバスの上に直接置きます。
- 実行ボタンは上のバーに置きません。

### Playground

```
┌ 上のバー ───────────────────────────────────────────────┐
│ ┌ コードのカード ───────────┐  流  ┌ 出力のカード ───────┐ │
│ │ 例の名前 ▾  main.ssrg      │  れ  │ 出力 [コンソール|画面] │ │
│ │                            │  ▶  │ › 結果                │ │
│ │ （ひとこと）               │ 実行 │                       │ │
│ │                            │  ┆  │ 次に試す: [チップ]…   │ │
│ └────────────────────────────┘      └───────────────────────┘ │
└ ● 準備できました · ドキュメント · GitHub ─────────────────┘
```

- コードのカードの見出しには、例の名前（押すと「探す」が例の一覧で開く）、ファイル名、解説、整形、元に戻すを置きます。
- 初めて開いたときだけ、書き換える場所を指すひとこと（コーチマーク）を出します。書くのは「何を変えるか」と「Tour への入口」だけです。
- 出力のカードには、結果の行、状態（`✓ 18 ms`）、「次に試す」のチップを置きます。チップを押すと、その書き換えがコードに入ります。

### Tour

```
┌ 上のバー ──────────────────────────────────────────────┐
│ 目次  第1章 · はじめの一歩 ▬▬▭▭  1/24 │ ┌ コード ────────┐ │
│                                         │ └────────────────┘ │
│ 最初のプログラムを動かす（題名）       │    ┄┄ ▶ 実行 ┄┄    │
│ 一文の導入                              │ ┌ 出力 ──────────┐ │
│ ┌ やってみよう ─────────┐               │ │ ✓ 期待どおり   │ │
│ └───────────────────────┘               │ └────────────────┘ │
│ コードを読む ①②  /  もう少し（折りたたみ）│                    │
│ ┌ 次へ: 次のレッスン名 → ┐              │                    │
└─────────────────────────────────────────┴────────────────────┘
```

- 左はレッスンの読み物です。本文はカードに入れず、キャンバスに直接置きます。「やってみよう」だけをカードにして目立たせます。
- 「コードを読む」の番号（①②）は、エディターの中にも同じ番号のピンとして出し、どこの話かを示します。
- 右は、コード・実行・出力を縦に並べます。Playground と同じ部品を、向きだけ変えて使います。
- 章の中の進み具合は、レッスンの数だけ区切ったバーで見せます。
- 目次はコースマップにします。章をカードで並べ、進み具合と「いまここ」を見せます。開いても上のバーは残します。

### モバイル（760px 以下）

| 段 | Playground | Tour |
| --- | --- | --- |
| 1 段目 | ロゴ、Playground / Tour、探す、JA / EN | 同じ |
| 2 段目 | 例の名前 ▾、整形、その他 | 目次、章の名前、区切りのバー、1/24 |
| 本体 | コード。下から出力のシートが顔を出す | レッスン。下の「レッスン / コード」で切り替える |
| 浮かぶもの | 右下に実行ボタン | コードを開いたときだけ、右下に実行ボタン |

- 出力のシートは、引き上げると画面の 7 割まで広がります。
- ひとこと（コーチマーク）は、コードに重ねず、コードの上に置きます。

### 探す（`⌘K`）

- 入力欄、範囲のチップ（すべて、例、レッスン、API、設定）、結果の一覧、キーの案内の順に並べます。
- 結果は種類ごとにまとめ、左のアイコンの形と色で種類を見分けられるようにします。
- 白紙から書く、最初の例に戻る、テーマ、文字の大きさも、ここから選べるようにします。
- モバイルでは、下から出るシートにします。

### 文字

| トークン | 値 | 用途 |
| --- | --- | --- |
| `--font-ui` | Geist、Noto Sans JP | 画面の文字 |
| `--font-code` | Geist Mono | コード、出力、数字の表示 |
| `--text-2xs` | 11px | 小見出し（大文字・字間広め） |
| `--text-xs` | 12px | タグ、補足 |
| `--text-sm` | 13px | ボタン、切り替え |
| `--text-md` | 14px | 本文の基準 |
| `--text-lg` | 17px | レッスンの導入文 |
| `--text-xl` | 22px | パレットの見出しなど |
| `--text-display` | 34px | レッスンの題名（モバイルは 26px） |
| `--code-size` | 14px / 行の高さ 24px | エディター（モバイルは 13px / 22px） |

- フォントは本番では自前で配信します。外部のフォント配信には頼りません。
- 見出しは字間を詰め（-0.02em）、太さは 700 にします。本文は 400、ボタンは 550〜600 です。
- 数字は等幅の数字（`tabular-nums`）にして、所要時間や進み具合が揺れないようにします。
- コードでは合字を使いません。

### 余白・形・影

| トークン | 値 |
| --- | --- |
| `--space-1`〜`--space-7` | 4 / 8 / 12 / 16 / 24 / 32 / 48px |
| `--radius-xs` / `sm` / `md` / `lg` | 6 / 8 / 12 / 16px |
| `--radius-full` | 切り替え、チップ、実行ボタン |
| `--top-h` | 60px（モバイルは 56px） |
| `--shadow-card` | カード。1px の線と、ぼかした薄い影 |
| `--shadow-float` | パレット、コーチマーク、浮かぶボタン |

### 動き

- 時間は 160〜220ms、曲線は `cubic-bezier(0.2, 0.8, 0.2, 1)` にそろえます。
- 実行すると、流れの線に沿って点が流れ、出力の行が上から順に現れます（1 行 60ms ずつ遅らせる）。
- `prefers-reduced-motion` が有効なら、動きをすべて止めます。

## 6. 日本語と英語

### 切り替えの置き場所

- 上のバーの右端に `JA` / `EN` を置きます。デスクトップでもモバイルでも同じ位置です。
- メニューの中には入れません。docs サイトでは、モバイルで言語の切り替えがメニューの中に隠れることが指摘されています（seseragi-docs #38 の 5）。

### どう覚えておくか

- 言語は URL のパスで表します。docs サイトと同じく、日本語は `/`、`/tour/`、英語は `/en/`、`/en/tour/` です。
- 切り替えても、今の場所は保ちます。開いている例、レッスン、書き換えたコード、出力はそのまま残します。
- 保存した好みで、別の言語のページへ自動で移動はしません。共有したリンクの言語が、開く人によって変わらないようにするためです。
- `/` を開いた人のブラウザの言語が日本語でないときは、一度だけ「English is available」の帯を出します。閉じたら、このブラウザでは二度と出しません。

### 何を訳すか

| 段 | 対象 | 英語版を出す時点での扱い |
| --- | --- | --- |
| 1. 画面の部品 | ボタン、ラベル、見出し（やってみよう、コードを読む など）、案内、エラーの枠 | すべて訳しておく。未訳のまま出さない |
| 2. 名前と一行の説明 | 例・章・レッスンの題名、一行の説明、例のグループ名 | 先に訳す。未訳なら日本語で出し、`Japanese only` の印を付ける |
| 3. 本文 | レッスンの本文、例の解説、設計の背景の記事 | 未訳なら日本語の原文を出し、本文の先頭に一行の案内を置く |
| 4. コード | 例やレッスンのコードの中の文字列とコメント | 英語版のコードがあればそれを出す。なければ日本語版。キーワードと名前は訳さない。期待する出力は、出したコードに合わせる |
| 5. コンパイラのメッセージ | エラーや警告の本文 | 今は英語だけ。どちらの言語でも原文のまま出す。周りの枠（「エラー 1 件」など）は訳す |

### 未翻訳のものの扱い

- 未訳のものを隠しません。Tour の順番が崩れ、例の数が言語で変わってしまうためです。
- 未訳の本文には `lang="ja"` を付け、読み上げが日本語で読めるようにします。
- 案内の文は「This lesson isn't translated yet. Its text is shown in the original Japanese. Buttons, code, and output work the same.」のように、何が未訳で何は変わらないかを一文ずつ書きます。
- 機械翻訳を自動で出しません。
- 英語では文字の幅が変わります。ボタンやチップは幅を固定せず、中身に合わせて伸ばします。

## 7. レイアウトと画面幅

| 幅 | Playground | Tour |
| --- | --- | --- |
| 1101px 以上 | コード 1.25 : 流れ 104px : 出力 1 | レッスン 440〜560px と、コード・実行・出力の縦並び |
| 761〜1100px | コード 1 : 流れ 88px : 出力 0.9。探すは虫めがねだけ | レッスンとラボを 1 : 1 |
| 760px 以下 | 「3. 画面の骨格」のモバイルの表 | 同じ |

- 画面幅による切り替えは、CSS ファイルの末尾の一か所にまとめます。
- モバイルのコードは横にスクロールさせず、行番号の幅だけ字下げして折り返します。docs サイトのコードブロックは横スクロールにする案が出ています（seseragi-docs #38 の 2）。エディターと読み物で方針を分けるかは、実装のときに決め直します。
- iOS のホームバーなどに隠れないよう、`env(safe-area-inset-*)` を余白に足します。

## 8. アクセシビリティ

- 文字と背景のコントラストは、ライトとダークの両方で 4.5:1 以上にします。
- キーボードで操作したときは、2px のアクセント色の枠でフォーカスを見せます。
- 色だけで状態を伝えません。成功には ✓、現在地には「いまここ」や番号を、文字と一緒に出します。
- 押せる領域は 36px 以上、タッチ操作では 44px 以上にします。
- 出力と状態のチップは `aria-live="polite"` で読み上げます。

## 9. やらないこと

- 現行のレイアウト、色、部品を前提にした手直し。
- 内部の分類名や実装の説明を、画面の文言として出すこと。
- 「実行」以外のボタンを、実行と同じ強さで目立たせること。
- Playground / Tour の切り替えや言語の切り替えを、メニューの中に入れること。
- 狭い画面で、ラベルや現在地を消すこと。
- 例、レッスン、API、設定ごとに別々の探す画面を作ること。
- 未訳のコンテンツを隠すこと。機械翻訳を自動で出すこと。
- トークンを通さずに、色や余白の値を直接書くこと。
- 書き換えた内容を、確認なしで消すこと。
