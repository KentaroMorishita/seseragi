# Playground / Tour デザインの決めごと（初版ドラフト・旧案）

> これは旧案（v1）です。現行の案は [`docs/design/playground/DESIGN.md`](../../DESIGN.md) を見てください。この文書の中のリンクは、旧案を置いていた場所を指しています。

Playground と Tour の画面を変える人のための文書です。見た目、言葉、操作の感触をそろえるための決めごとをまとめます。

- 何をどこに置くか（画面の役割と導線）は [`INFORMATION_ARCHITECTURE.md`](./INFORMATION_ARCHITECTURE.md) が決めます。
- この文書は、それをどう見せるか、どう感じさせるかを決めます。
- 画面案の静的モックは [`design/mock/`](./design/mock/index.html) にあります。

> この版はドラフトです。数値や言い回しは、モックを見ながら決め直してかまいません。

## 1. 体験の原則

### まず触って気持ちいい

- 開いた瞬間に、動くコードとその結果が見えている状態にします。最初の操作は「書き換えて実行」です。
- 最初に見せるコードは、Seseragi らしさ（`type` と `match`、`|>`）が一目で分かる、10 行前後のものにします。
- 実行は速く、結果ははっきり見せます。成功したら「✓ 実行しました」と所要時間を、失敗したらエラーの場所と直し方を出します。

### 内部用語を画面に出さない

- 画面の文言は、初めて来た人が読んで分かる日本語で書きます。
- 設計文書の分類名（Recipe、Showcase、surface、facet）、実装の名前（registry、manifest、canonical）、開発者向けの言葉（diagnostic、source、workspace）は画面に出しません。
- 言語のキーワードと型名（`fn`、`match`、`Int`、`Effect`、`Signal`）はそのまま使います。固有名の Seseragi、Playground、Tour もそのまま使います。
- 置き換え表は「3. 画面の言葉」にあります。

### 主役は一つ

- 一つの画面で一番目立つボタンは「実行」だけにします。
- 「次へ」や「例を探す」は、アクセントの枠線か控えめなボタンで見せます。

### 次の一歩をいつも見せる

- 結果のそばに「次に試すこと」を置き、そこからコードの書き換え、ほかの例、Tour へ進めるようにします。
- Tour では、各レッスンの終わりに次のレッスン名を出します。

### 説明は少しずつ開く

- 最初に見せるのは「何をするか」と「やってみること」だけにします。
- よくある間違いや設計の背景は折りたたみの中に置きます。読みたい人だけが開きます。

### 狭い画面でも削らずに畳む

- モバイルでも、今どの例やレッスンを開いているかは必ず見せます。
- `font-size: 0` や `display: none` でラベルを消しません。入りきらない操作は、名前付きのメニューへ移します。

### 失敗はやさしく

- エラーはコードの該当行と出力の両方に出します。文面は「何が起きたか」と「どう直すか」の順に書きます。
- 書き換えた内容を黙って消しません。「元に戻す」は確認してから行います。

## 2. デザイントークン

トークンは CSS のカスタムプロパティとして `:root` に一か所で定義します。値はモックの `design/mock/mock.css` と同じです。

### 色

暗い背景に、せせらぎの緑をアクセントとして使います。今ある配色を引き継ぎ、名前を付けて整理したものです。

| トークン | 値 | 用途 |
| --- | --- | --- |
| `--bg-app` | `#08100e` | 一番奥の背景、コードの出力枠 |
| `--bg-panel` | `#0c1613` | ペイン、ヘッダー、状態バー |
| `--bg-raised` | `#12201b` | カード、ボタン、選択ピッカー |
| `--bg-hover` | `#182a23` | ホバー、選択中のタブ |
| `--line` | `#1c2d27` | 区切り線 |
| `--line-strong` | `#2c463d` | 操作できる部品の枠 |
| `--fg-1` | `#e3efea` | 本文、見出し |
| `--fg-2` | `#a9bdb5` | 補足の文 |
| `--fg-3` | `#7a8f87` | ラベル、目立たせない情報 |
| `--accent` | `#7ed6ad` | 実行ボタン、現在地、成功 |
| `--accent-strong` | `#a6ebc9` | アクセント上の強調、ホバー |
| `--accent-soft` | 緑の 12% | 「やってみよう」の面、選択中のチップ |
| `--on-accent` | `#06231a` | アクセントの面に載せる文字 |
| `--warn` | `#f1b37a` | 警告、書き換える場所の印 |
| `--error` | `#ff8a96` | エラー |
| `--info` | `#82b9f6` | お知らせ |

コードの色は [`src/editor/syntax-theme.css`](./src/editor/syntax-theme.css) の値をそのまま使います。

コントラストは次のとおりで、どれも WCAG AA の 4.5:1 を満たします。

| 文字 | `--bg-app` | `--bg-panel` | `--bg-raised` |
| --- | --- | --- | --- |
| `--fg-1` | 16.3 | 15.6 | 14.3 |
| `--fg-2` | 9.7 | 9.3 | 8.5 |
| `--fg-3` | 5.6 | 5.4 | 4.9 |
| `--accent` | 11.1 | 10.6 | 9.7 |

`--on-accent` と `--accent` の組み合わせは 9.6:1 です。

### 文字

| トークン | 値 | 用途 |
| --- | --- | --- |
| `--font-ui` | Inter、ヒラギノ角ゴ、Noto Sans JP | 画面の文字 |
| `--font-code` | JetBrains Mono、等幅のシステムフォント | コード、出力 |
| `--text-xs` | 12px | 補足ラベル、タグ |
| `--text-sm` | 13px | ボタン、ペインの見出し |
| `--text-md` | 14px | 本文（画面の基準） |
| `--text-lg` | 16px | レッスンの導入文、節の見出し |
| `--text-xl` | 20px | ダイアログの見出し |
| `--text-2xl` | 26px | レッスンの題名（モバイルは 22px） |
| `--code-size` | 14px | エディターと出力（モバイルは 13px） |

- 本文の行の高さは 1.6、コードは 1.7 にします。
- コードでは合字を使いません（`->` や `|>` を記号のまま見せます）。
- 太さは 400（本文）、600（ボタン、見出し）、700（題名、実行ボタン）の三段階だけにします。

### 余白と形

| トークン | 値 |
| --- | --- |
| `--space-1`〜`--space-6` | 4 / 8 / 12 / 16 / 24 / 32px |
| `--radius-sm` / `md` / `lg` | 6 / 10 / 14px |
| `--control-h` | 36px（モバイルは 44px） |
| `--bar-h` | 56px（モバイルは 52px） |
| `--status-h` | 28px |

余白は 4 の倍数だけを使います。部品の中は 8〜12px、部品の間は 12〜16px、まとまりの間は 24〜32px が目安です。

### 動き

- 開閉や切り替えは 120〜180ms の短い変化にします。
- `prefers-reduced-motion` が有効なら、動きをなくします。

## 3. 画面の言葉

| 今の表示 | 画面での言い方 | メモ |
| --- | --- | --- |
| Run | 実行 | ショートカット `⌘↵` を添える |
| Output / Input | 出力 / 入力 | |
| Text / Preview | テキスト / 画面 | 出力の表示切り替え |
| Format | 整形 | |
| Reset | 元に戻す | |
| Explorer | ファイル | アイコンだけにするときも `aria-label` に名前を付ける |
| Workspace（sample selector） | 例 | 選択中の例の名前を見せる |
| Discover | 例を探す | |
| Blank workspace | 白紙から書く | |
| Recipe / Showcase | 小さな例 / 完成した作品 | 絞り込みの名前として使う |
| Featured | おすすめ | |
| Guide | 解説 | |
| diagnostic | エラー / 警告 | |
| source / code | コード | |
| lesson / Curriculum | レッスン / 目次 | |
| 課題sourceを開く | 答えを見る | 先に自分で書き換えてもらう |
| Settings / Reference | 設定 / リファレンス | |
| Full screen | 全画面 | |

文の書き方は次のとおりです。

- 「〜します」「〜しましょう」で書きます。命令形や体言止めの羅列は避けます。
- 一文に一つのことだけを書きます。ボタンは動詞で終えます（「例を探す」「答えを見る」）。
- 実装の説明（どこから生成しているか、どの方式で動くか）は画面に書きません。

## 4. コンポーネントの決めごと

### ヘッダー

- 左から、ロゴと名前、Playground と Tour の切り替え、画面ごとの道具、右端に「その他」と「実行」を置きます。
- Playground と Tour の切り替えは、両方の名前が常に見える二択の切り替えにします。どちらの画面でも同じ位置、同じ形にします。
- Tour では、ヘッダーの中央に章の名前、進み具合のバー、「1 / 24」の形の現在地を置きます。

### ボタン

| 種類 | 見た目 | 使う場面 |
| --- | --- | --- |
| 主役 | アクセントの面 | 「実行」だけ |
| 次へ | アクセントの枠と薄い面 | Tour の「次へ」、ダイアログの決定 |
| 通常 | `--bg-raised` の面と枠 | 「答えを見る」「ほかの例を見る」 |
| 控えめ | 枠なし | ペインの見出しにある操作（整形、解説） |
| リンク | アクセント色の文字 | 別の画面へ移る（Tour で順に学ぶ →） |

- アイコンだけのボタンにも、日本語の `aria-label` と `title` を付けます。
- 押せる領域は、デスクトップで 36px、タッチ操作で 44px 以上にします。

### 選択ピッカー（例・目次）

- 「例 天気のアドバイス ⌄」のように、短いラベル、選択中の名前、開く印の順に並べます。
- 名前が長いときは末尾を「…」で省略します。名前そのものは消しません。

### ペイン

- 見出しの高さは 48px です。左にペインの名前か選択ピッカーを、右に操作を置きます。
- 出力の見出しには、表示の切り替え（テキスト / 画面）と「入力」を置きます。めったに使わない操作（消去、全画面）は「その他」へ入れます。

### コードと出力

- 行番号は控えめな色にします。今読んでいる行には左端にアクセントの線を引き、書き換えてほしい場所には点線の下線を引きます。
- 出力の上に「✓ 実行しました · 18ms」のような結果の行を出します。
- Tour では、期待する出力と一致したら「✓ 期待どおりの出力です」と出します。

### 歓迎の帯（Playground の初回だけ）

- ヘッダーの下に一行で出します。閉じたら、このブラウザでは二度と出しません。
- 書くのは、コードがそのまま動くことと、Tour への入口の二つだけです。

### 「次に試すこと」カード

- 出力の下に置きます。一つの書き換えの提案と、ほかの例、Tour への導線を載せます。
- 中身は例ごとの解説（guide）から一つ選んで出します。

### ダイアログ「例を探す」

- 見出しの下に、白紙から書く、最初の例に戻る、今の例を元に戻す、の三つを並べます。
- 検索欄と絞り込みのチップ（すべて、おすすめ、小さな例、完成した作品、画面を作る、入力を使う）を置きます。
- 例はグループごとにカードで並べます。カードには、やりたいことの形の題名、一文の説明、タグを載せます。
- モバイルでは画面の下から出るシートにします。

### Tour のレッスン

レッスン本文は次の四つのまとまりだけにします。

1. 題名と一文の導入
2. 「やってみよう」カード：自分で手を動かす手順を一つか二つ。終わった手順にはチェックが付きます。「答えを見る」と「最初のコードに戻す」もここに置きます。
3. 「コードを読む」：行番号付きの短い説明。選ぶと、エディターの該当行が強調されます。
4. 折りたたみ：「よくある間違い」と「もっと詳しく」

- レッスンの下端に「← 前へ」と「次へ: 次のレッスン名 →」を固定します。
- 目次は左から出る引き出しにします。本編（章ごと）と寄り道（いつでも読める補足）を分けて見せます。

### モバイルのタブバー

- 画面の下に置きます。Playground は「コード / 出力」、Tour は「レッスン / 試す」です。
- 実行して新しい結果が出たら、出力のタブに点を付けて知らせます。
- 上部は「ヘッダー」と「選択ピッカーの行」の二段までにします。

## 5. レイアウトと画面幅

| 幅 | Playground | Tour |
| --- | --- | --- |
| 1181px 以上 | コード 6 : 出力 4 | レッスン 380〜460px と、コード・出力の上下二段 |
| 761〜1180px | コード 6 : 出力 4（ファイル一覧は重ねて表示） | レッスンと、コード・出力。目次は引き出し |
| 760px 以下 | 一列。下のタブで切り替える | 一列。下のタブで切り替える |

- 画面幅による切り替えは、各 CSS ファイルの末尾の一か所にまとめます。同じ幅の `@media` を複数の場所に書きません。
- モバイルのコードは横にスクロールさせず、行番号の幅だけ字下げして折り返します。
- iOS のホームバーなどに隠れないよう、`env(safe-area-inset-*)` を余白に足します。

## 6. アクセシビリティ

- 文字と背景のコントラストは 4.5:1 以上にします（「2. デザイントークン」の表を参照）。
- キーボードで操作したときは、2px のアクセント色の枠でフォーカスを見せます。
- 色だけで状態を伝えません。成功には ✓、現在地には ● を、文字と一緒に出します。
- 出力と、実行の結果の行は `aria-live="polite"` で読み上げます。

## 7. やらないこと

- 内部の分類名や実装の説明を、画面の文言として出すこと。
- 「実行」以外のボタンを、実行と同じ強さで目立たせること。
- 狭い画面で、ラベルや現在地を `font-size: 0` や `display: none` で消すこと。
- ヘッダーへ新しいボタンを直接足すこと。作用する範囲を決めてから、ペインかメニューへ置きます（`INFORMATION_ARCHITECTURE.md` の五層）。
- 同じ画面幅の `@media` を一つのファイルの複数の場所に書くこと。
- トークンを通さずに、色や余白の値を直接書くこと。
- 書き換えた内容を、確認なしで消すこと。
- 今回は、ライトテーマ、テーマの切り替え、英語の画面は作りません。トークンの名前は、あとで足せる形にしておきます。
