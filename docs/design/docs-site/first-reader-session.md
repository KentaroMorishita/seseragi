## 読者へ渡す課題

最初は説明を補わず、本文を頼りに進めてもらう。止まったらその場所と疑問を
記録し、必要な補助説明をした後で続ける。完了までの時間で合否を決めない。

1. ホームから、言語の紹介とDocsの入口を探す。どんな用途に使えそうか、
   TypeScriptの例と同じところ・違うところを、自分の言葉で説明する。
   期待した情報が見つからなければ、探したページと見出しを記録する。
2. 自分の最初のプログラムを動かす手順を探す。OSに合った説明だけを使い、
   新しい作業ディレクトリでファイルを作り、確認して実行する。
   表示された結果を残し、文字列を変更してもう一度動かす。
   既存プロジェクトのファイルは使わない。
3. 値と名前の記事へ進む。例の入力と結果を説明し、更新前の値がどうなるか
   予想する。TypeScriptの`const`との違いが読み取れたか記録する。
4. 基本の型と型注釈の記事で、例の値に合う型、関数名、各引数、戻り値、
   本体を指し示す。型を書くことと値を変換することの違いを説明する。
5. 関数呼び出しの記事で、定義済みの関数へ全部の引数を渡す。
   入力を一つ変えた結果を予想し、実行結果と比べる。
   TypeScriptと同じ括弧の書き方で迷った場合は、その箇所も記録する。
6. ブロックの記事で、どの行が結果になるか説明する。局所的な名前を
   ブロックの外で使えるか、本文から判断する。
7. 関数型とカリー化の記事で、一部の引数だけを渡した時点で何が得られるか、
   残りの引数を渡すと何が返るか説明する。最初の普通の呼び出しと比べる。
8. 知りたい規則をもう一度探す。記事内の見出し、関連リンク、カテゴリの
   どれを使ったかを記録する。別の記事から戻れたかも確かめる。
