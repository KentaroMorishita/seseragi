# API ドキュメントの出力

`seseragi doc` が作るファイルの中身と、作るときの決まりをまとめます。
コマンドの使い方と終了コードは、仕様の [12章](../spec/12-tooling.md) にあります。
この文書は、出力を変える開発者に向けたものです。

## 出力するファイル

`seseragi doc <package>` は、既定で `dist/doc/` に次の3種類を書き出します。

| ファイル | 中身 |
| --- | --- |
| `index.html` と各ページ | 公開 API の説明。JavaScript は含まない |
| `search-index.json` | 検索用のデータ。HTML に埋め込まず、別のファイルにする |
| ソースのページ | 宣言の元のソース。HTML として安全な形に直して載せる |

型や既定値は、コンパイラーが調べた結果だけを使います。ドキュメントコメントの文章から、型や既定値を決めることはありません。

## `search-index.json`

先頭に次の値を持ちます。

- `schema: 1`
- `kind: "seseragi-api-document"`
- 生成したツールの名前と版、パッケージの名前と版

`modules` にモジュール、`symbols` に宣言を並べます。各宣言は次を持ちます。

- コンパイラーが使う一意な名前、名前空間、利用者が書く名前
- 型を調べた結果のシグネチャ、ソースの範囲、ページへのリンク
- メンバーなら、それを持つ型
- 非推奨なら `deprecated: { message, since? }` と、`deprecated` 句を書いた位置。非推奨でなければ、この2つの項目を持たない

リンクが解決できなかった箇所などの警告は、位置つきで `warnings` に入れます。

## 公開範囲

公開するモジュールは、パッケージの `exports` に書いたものだけです。
`--include-private` を付けると、ほかのモジュールと非公開の宣言を `scope: "private"` として加えます。
公開 API のコメントから、非公開の宣言へリンクすることはできません。

## コメント内のリンク

- リンク先は、宣言のモジュール、名前空間、メンバーの持ち主から決めます。
- モジュール名つきの書き方と、明示的に import した別名は、元の宣言を指します。
- 見つからない、候補が複数ある、公開されていない、のどれかなら、リンクにせず文字のまま残し、警告を出します。
- 別のモジュールから再公開された宣言で、元のソースがないときは、ソースへのリンクで再公開した位置と元の宣言を区別します。
- 警告の位置は、コメントの元の UTF-8 のバイト位置で示します。

## Markdown の描画

- CommonMark を表つきで描画します（pulldown-cmark）。
- コメントに書いた HTML は、HTML として扱わず文字として表示します。
- リンク先の URL は、`http:`、`https:`、`mailto:` と、スキームのない相対パスだけを残します。`javascript:` などほかのスキームは、空にします。

## 書き出しの手順

1. `--test` を付けたときは、先にコメント内のコード例をすべて実行します。
2. 一時的なディレクトリに、出力を全部作ります。
3. 作り終えたら、出力先と入れ替えます。前回の出力のうち、今回作らなかったファイルは消します。

コード例が失敗したとき、またはパッケージのコンパイルに失敗したときは、前回の出力を1バイトも変えません。
入れ替えに失敗したときは、前回の出力に戻します。戻すことにも失敗したときは、前回の出力を別の場所に残し、その場所を表示します。

出力先が `seseragi doc` の作ったものかどうかは、ディレクトリに置く目印のファイル（`.seseragi-api-document`）で見分けます。
同時に2つの `seseragi doc` が同じ出力先へ書かないように、出力先にロックファイル（`.seseragi-doc.lock`）を作ります。
次の場合は、利用者のファイルを守るために書き出しを止めます。

- 出力先がシンボリックリンクのとき
- 目印のない、空でないディレクトリのとき

## しないこと

- サイトを公開する、サーバーを起動する
- `--test` を付けないときに、コード例を実行する
