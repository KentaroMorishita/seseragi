# 仕様の機能と、それを確かめる例の対応表

仕様（`docs/spec/`）の機能ごとに、それを学ぶ教材と、機械で確かめる fixture を対応づけた表です。
仕様を書き足す人と、実装がどこまで仕様に追いついたかを知りたい人に向けたものです。

## 状態の意味

| 状態 | 意味 |
| --- | --- |
| 済み | 確かめる対象のソースがある |
| 一部 | 一部の対象はあるが、まだ足りないものがある |
| 予定 | 必要な対象は分かっているが、まだ作っていない |

コンパイラーが仕様に適合したと言えるのは、必要な行がすべて「済み」になり、成功と失敗の両方を確かめるべき機能では、診断の fixture も通るときです。

## 2種類の例

- `examples/spec/lessons/` は、仕様が決めた言語を学ぶ教材です。
- `examples/samples/` は、今のコンパイラーで動く、Playground と CLI のサンプルです。

この2つの状態を混同しません。

プロジェクトの fixture は、`fixtures/projects/inventory.json` で `availability: current` になっていて、ふつうの実行器での確認の記録があるときだけ、今の実装で確かめたものとして数えます。
`contract-only` は、仕様の約束がどこにあるかを示すだけで、実装済みや CI で実行済みという意味ではありません。
